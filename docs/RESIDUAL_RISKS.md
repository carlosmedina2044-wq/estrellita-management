# Residual risks

| Risk | Why it is accepted | Compensating control |
|---|---|---|
| Unlocked, stolen iPhone with the app already open | Any local app shares this risk | Lock-after timer (immediate / 2 min / 15 min) re-locks on background using timestamps on `pause`/`resume`, suppressed while an owner prompt is in flight; Face ID / ACL prompt on relaunch; privacy blur in the app switcher; lock clears in-memory `CryptoKey` and household plaintext after flushing queued vault writes. |
| Device passcode holder can unlock the vault | iOS trust model: passcode is root; ACL is `biometryCurrentSet` **OR** `devicePasscode` | Documented in-app; no weaker fallback exists. Passcode holder can still open the home. |
| Removing the device passcode deletes the Keychain item | `WhenPasscodeSetThisDeviceOnly` by design | App shows a passcode-required screen (`passcode_required`) with Open Settings; restore from backup after setting a passcode again. Minting/migrating refuses when `deviceOwnerAuthentication` is unavailable. |
| Biometric enrollment change invalidates the Keychain item | `.biometryCurrentSet` by design | Maps to key-mismatch + Restore from backup / Erase. Backup password is the portability path. Quarantine never deletes Keychain accounts (`keyId` slots). |
| Data lost with the device / new iPhone | Vault key is `WhenPasscodeSetThisDeviceOnly` and does **not** migrate via Quick Start or encrypted backups | In-app encrypted export/import (“Back up my home”) is the cross-device path. Pre-restore snapshot + one-session undo mitigates accidental replace. Teach once after upgrade. |
| Forgotten backup password | Password is never stored; Cuidala cannot reset it | File is useless without it; honest copy in Settings and Additional terms. |
| `script-src 'unsafe-inline'` in CSP | Next.js static export emits per-build inline bootstrap scripts | No third-party scripts, no HTML from user input, `connect-src 'self'`, no server. Revisit if Next supports hashed inline scripts in export mode. |
| Web shell stores the key in `localStorage` | Dev-only surface | README states it is unsupported for end users. |
| Apple WeatherKit / geocoding sees ZIP or coordinates | Needed for forecasts and climate setup | Native WeatherKit + `CLGeocoder`; Apple-collected only — Cuidala has no server. Usage strings and in-app privacy copy state this honestly. Climate zone still uses on-device ZIP-3 tables. Users may skip location and type a ZIP, or skip both. |
| Retailer sites opened by the user are third parties | Inherent to deep-linking | SFSafariViewController isolation; app never sees the session; `http:` upgraded to `https:` before open. |
| **Notification content (item names) can show on the lock screen when private mode is off (S7).** | Needed so the nudge is useful without opening the app | In-app toggle “Hide item names on the lock screen” (`privateNotifications`); when on, bodies are fully generic. Users can also disable notifications in iOS Settings. No push, no server. |
| Manual verification items in the control matrix | No device CI yet | Run the checklist in `docs/INCIDENT_RESPONSE.md` §"Pre-release device checks" (including Phase 5 extras) before each TestFlight build. |
| **Texas SB 2420 / Declared Age Range (Q11).** The law is in force for new Texas Apple Accounts; Apple says App Review is unchanged and developers choose when to adopt Declared Age Range, PermissionKit Significant Change, and related APIs. | v1 has no accounts, no IAP, no age-gated features, and a 4+ rating | Decision for v1: do **not** call Declared Age Range. Revisit if Pro/StoreKit or household sharing (accounts) ships. Server notifications are moot without a server. |
| **Dynamic Type / Larger Text.** Root type uses `-apple-system-body` with rem tokens (`.ui-display` … `.ui-caption`). Some leftover `text-[Npx]` sizes and the 11px WeatherKit legal mark do not scale. | Remaining pixel sizes are captions and legal marks | System appearance follows `prefers-color-scheme`. Revisit leftover pixel sizes before claiming Larger Text in the Accessibility Nutrition. |
| **WKWebView VoiceOver / Assistive Access.** Capacitor WebView may not expose full native traits. | Architecture | Do not claim VoiceOver or Assistive Access Nutrition Labels until device proof. Document checklist in INCIDENT_RESPONSE. |
| **Never-completed starter quarterlies/yearlies shift first due by at most 3 weeks once.** Existing seeds wrote `dueDate = createdAt + weekOffset*7`. After M1-01, `nextDueDate` honors that `dueDate` as-is instead of `createdAt`. No migration. | One-time schedule move for already-seeded homes; new seeds use `firstDueInDays` (M1-02) | Completions and `installedAt` still win; restock replacements keep their install-date cadence. |
| Playbook tasks without an explicit `topic` are never dropped, even when they overlap a starter by meaning. | No fuzzy match by design; titles differ across catalogs | Five colliding all-safety / new-home tasks are tagged (`smoke-detectors`, `dryer-vent`, `fridge-coils`, `hvac-filter`). New overlapping playbook tasks must set `topic`. |
| **Momentum data (closed-day run, week progress, milestones) is derived from local completions.** It is stored on-device in the household vault and cleared by erase-all. A Settings switch hides the UI; numbers keep accruing. | No server, analytics, or extra input; the layer is optional encouragement | Erase-all removes the vault plaintext, including `momentum` and `milestones`. Turning the switch off does not delete history. |
| Icon Composer `.icon` not shipped for iOS 26 layered variants | Asset pipeline; AppIcon.appiconset is terracotta-on-cream for 1.0 | Do not block submission unless App Store Connect requires Icon Composer assets; revisit for a later OS polish pass. |
| Capacitor / Cordova xcframework signature warnings at Validate | Upstream packaging | Archive with Xcode 26 → Validate App; confirm SDK signatures before Distribute. |
