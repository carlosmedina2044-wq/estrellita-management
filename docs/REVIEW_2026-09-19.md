## Summary

The core security design holds up: AES-256-GCM vault, Keychain-bound key behind Face ID / passcode, strict CSP, no remote code, no secrets in the repo, privacy manifests and entitlements consistent with the docs. ## High

### 1. Keychain plugin returns the wrong key
`plugins/cuidala-device-key/ios/Sources/CuidalaDeviceKeyPlugin/CuidalaDeviceKeyPlugin.swift:144`

`read(key:)` always reads the legacy `cuidala-device-key-v2` account first and returns it if present, whatever account JavaScript asked for. The keyId contract in `src/lib/native/device-key.ts:89` is therefore not honoured natively whenever a v2 item exists.

**Failure scenario.** A user has a v2 key. Any AEAD failure on the vault (for example a UserDefaults vault restored onto a phone that has its own v2 key) makes `resolveDeviceKeyForPersist` (`src/lib/storage/vault.ts:196`) quarantine the vault and mint keyId `abc` while v2 stays in the Keychain by design. Next launch: envelope keyId `abc` → `get("cuidala-device-key-abc")` → native returns v2's bytes → decrypt fails → `key-mismatch` → restore → quarantine again → new keyId → repeat. The household never opens.

Secondary: `delete(key:)` (line 336) with a specific key also deletes v2, v1 and the legacy account. Only `remove({ key: "" })` is called from JS today, so this is latent.

**Fix.** Read only the requested account; run the v1 → v2 legacy migration only when the requested account is v2; make `delete(key:)` delete just the named account.

### 2. Dead "Open Settings" button on the passcode-required recovery screen
`src/components/app-shell.tsx:1065`

`Browser.open({ url: "app-settings:" })` goes through `@capacitor/browser`, whose iOS implementation only opens `http` and `https` (`Browser.swift:19`); the call rejects and the empty `catch` swallows it. This is the one screen where the user is locked out of all their data and the primary button does nothing.

**Fix.** Use `App.openUrl({ url: "app-settings:" })` from `@capacitor/app`, and toast on failure.

### 3. Weather triggers never match today's forecast day in US time zones **[probed]**
`src/lib/weather/provider.ts:91`

`Date.parse("2026-09-19")` is UTC midnight, which is the previous evening west of Greenwich, so today's day fails `time >= start`. `src/lib/playbooks/playbooks.test.ts:379` explicitly works around this ("use tomorrow's calendar date") instead of the code being fixed. Freeze, heat, wind and rain for the current day are silently missed by both `evaluateTriggers` and the Seasonal view.

**Fix.** Parse with the local `parseISODate` helper and compare calendar days.

### 4. A weather trigger never re-creates its chores after they are completed once **[probed]**
`src/lib/weather/provider.ts:141`

`already` matches any unarchived duty with the same trigger id and title; tasks are `frequency: "once"` and nothing in the app ever sets `archived: true`. A hard freeze on Dec 2 adds three duties; the user completes them; a second hard freeze on Jan 16 records a fire but adds zero duties.

**Fix.** Treat a completed one-off duty as not blocking (mirror `liveDuties` in `duty-topics.ts:93`), or re-date the existing duty.

### 5. Budget forecast double-counts replacement chores that have a priced supply item **[probed]**
`src/lib/forecast/index.ts:302` (duty loop) vs `:247` (automation loop) and `:219` (consumables loop)

`applyCompletionCost` (`src/lib/costs.ts:98`) copies a recorded cost to both the completion and the linked automation's `lastPaidPrice`, and the three forecast loops are independent. One quarterly filter costed at $22 produces 6 lines / $132 a year instead of 4 / $88. `suggestedMonthlySetAside`, `fundHealth.coveragePct` and the budget insights inherit the inflation.

**Fix.** In the duty loop skip duties linked to a `SupplyAutomation` or whose asset already has a `Consumable`.

### 6. Restock item stuck in "Order now" forever **[probed]**
`src/lib/restock.ts:235` (fallback), `:663` (receive never advances the date), `src/lib/household-update.ts:124`

When `upcomingDutyDates` is empty (one-off duty completed, or duty deleted) the placement falls back to a stored `orderByDate` that nothing moves forward. Once it is past, the item is `order_now` every day regardless of stock, and each receipt inflates the learned rate because every "cycle" is only the lead time.

**Fix.** Advance `orderByDate` on receive from `lifespanDaysFor`, or use the rate/lifespan runway when no live duty dates exist.

### 7. Six-month restock items are scheduled as monthly chores **[probed]**
`src/lib/onboarding/restock-walk.ts:80`; catalog entries at `:132`, `:198`, `:275`

`Frequency` has no semi-annual value and `cadenceForInterval(6)` picks `monthly`. Fridge, air-purifier and well filters get a duty due today and every month, and the modelled consumption is 1 per 30 days for a 180-day filter. Only the 1-month case is covered by `restock-walk.test.ts`.

**Fix.** Add a semi-annual frequency, or let the lifespan drive the cadence and never emit a cadence faster than the lifespan.

## Medium

### 8. Erase-all leaves encrypted data behind
`src/lib/storage/vault.ts:567`, `:616`, `:634`; `plugins/cuidala-weatherkit/.../CuidalaWeatherKitPlugin.swift:59`; `ios/App/App/WeatherRefresh.swift:159`

`eraseHousehold` removes three keys, but every timestamped quarantine slot (`cuidala-vault-v2-unreadable.<ts>`) and every pre-restore snapshot slot (`cuidala-vault-snapshot.<ts>`) stays in UserDefaults forever. Each can be up to 8 MB of ciphertext, they are never enumerated, and they accumulate without bound. On the native side `clearWatchList` removes only the watch list; the `cuidala.weatherFired.<id>` markers survive, so after erase-all a new home's first freeze alert is suppressed for the old cooldown. Contradicts the control matrix's erase-all row.

**Fix.** Enumerate Preferences keys by prefix on erase (and cap the number of snapshot slots); remove `cuidala.weatherFired.*` in `clearWatchList`.

### 9. The "delete-safe" Keychain write is not delete-safe
`CuidalaDeviceKeyPlugin.swift:272-290`

The pending copy is deleted at line 290 before the result of the final `SecItemAdd` is checked, and no read path ever consults `<account>.pending`. If the final add fails (or the process dies between the delete at line 273 and the add at line 289), the device has no key and the next launch reports `key-mismatch`.

**Fix.** Delete the pending copy only after the add succeeds; in `read`, promote a pending item when the primary is missing.

### 10. App-switcher privacy screen is legible
`ios/App/App/SceneDelegate.swift:33`

`.systemUltraThinMaterial` is the most translucent system material; duty titles and restock names remain readable through it in the app switcher.

**Fix.** Cover with an opaque view in `CuidalaBridgeViewController.shellBackground`, or at least `.systemThickMaterial`.

### 11. Widget memory is close to the extension limit
`ios/App/CuidalaWidget/CuidalaWidgetSnapshot.swift:118`, `CuidalaWidget.swift:177`

Every render decodes six 936×672 RGBA layers with `UIImage(contentsOfFile:)` and no downsampling: roughly 2.5 MB each, about 15 MB per entry, against a 30 MB extension ceiling, with small and medium families rendered concurrently. The "~150 KB" in the docs is the compressed size. Not measured on device.

**Fix.** Decode through ImageIO thumbnails sized to the widget's points × scale, or pre-composite one image per phase in the app.

### 12. Settings name fields overwrite a restored backup
`src/components/home-view.tsx:136`; `src/components/home-editor.tsx:47`

The home / owner / cleaner inputs are seeded once via `useState` and never re-synced, while restore and undo live on the same screen. Blurring a field after a restore compares the stale local values to the new household and writes the pre-restore names back. `HomeEditor` keeps pre-restore floor and room ids the same way, so "Add room" after a restore can attach to a floor that no longer exists.

**Fix.** Reset local state when the source prop changes, as `DebouncedTextInput` already does.

### 13. Receive and order drafts are initialised once
`src/components/restock-order-flow.tsx:718` (`costDraft`), `:123` (`qtyDraft`)

The dialogs stay mounted for the life of the row, so the drafts never pick up a new `suggestedCost` or `qtyPerOrder`. Second-cycle receipts record no price even though one is known. `OrderConfirmSheet` (`:474`) does this correctly.

### 14. Long-press chore menu can render under the tab bar
`src/components/duty-context-menu.tsx:83`; `src/app/globals.css:422`

The menu is `position: fixed` inside `.app-shell-roots`, whose `will-change: transform` makes it the containing block and a stacking context. The tab bar is a later sibling, so it paints above the menu regardless of `z-60`; near the bottom of Today, Edit and Delete are untappable. `ParticleLayer` and `WindowZoomLayer` are contained the same way.

**Fix.** Portal the menu to `document.body` and clamp `top` against the tab-bar height.

### 15. Turning Face ID on mid-session tears down the whole tree
`src/components/app-shell.tsx:317`, `:655`; `src/components/home-view.tsx:642`

`locked` starts true and is never cleared on Face ID devices with the setting off. Enabling the switch writes `requireFaceId`, the vault mirrors it into `sessionMeta` on the same write, and the gate flips: the main tree is replaced by `FaceLock`, and after unlocking every keep-alive pane remounts (celebration, reveal, scroll state lost). Possibly intended as an enrolment check, but undocumented and side-effectful.

### 16. Momentum and milestone maths freeze the UI **[probed]**
`src/lib/momentum.ts:604`; `src/lib/duties.ts:22`; `:545`

`newlyEarned` runs all predicates, `runReached` re-walks the run three times, `dayOutcome` rebuilds the household per day, and `lastCompletion` filters and sorts all completions on every call. With 40 duties and 12 months of history (4.2k completions; cap is 20k), a check-off took 1.25 s and the Year view 2–5 s under Node on an M-series Mac.

**Fix.** Index completions by duty once per call tree; memoise `dayOutcome`; compute the run once.

### 17. Empty cost input saves as $0 **[probed]**
`src/lib/costs.ts:12`

`Number("")` is 0, which passes the `< 0` guard; `cost-prompt.tsx:40` enables Save whenever the parse is non-null. The zero becomes `lastPaidPrice`, wins `blendedCostFor`, and suppresses cost prompts for 30 days.

### 18. Deleting a room orphans its consumables **[probed]**
`src/lib/home-model.ts:220`

Assets are removed but `household.consumables` are not filtered, so they keep feeding the forecast, and `roomHasAssignedWork` never sees them.

### 19. Learned consumption rate overstates use every cycle **[probed]**
`src/lib/restock.ts:458`

`impliedRate = confirmed / daysBetween` assumes every confirmed unit was used up by the next receipt. Because orders are placed before run-out, each receipt overstates the rate; over four cycles the interval shrank from 151 to 119 days and stock accumulated. `applyCheckin` (`:423`) already does it right.

### 20. Rhythm counts miss the completion made exactly one cadence ago **[probed]**
`src/lib/duty-history.ts:39`

`d > windowStart` on day-aligned stamps excludes the boundary, so a daily streak reads 0 every morning and a six-week Monday streak reads 5 of 6.

**Fix.** Half-open window `d >= windowStart && d < windowEnd`.

### 21. Xcode hardening is off
`ios/App/App.xcodeproj/project.pbxproj:358` (project), `:467` (targets); `App.entitlements`; `CuidalaWidget.entitlements`

No `SWIFT_STRICT_CONCURRENCY`, `SWIFT_VERSION = 5.0`, no `SWIFT_TREAT_WARNINGS_AS_ERRORS`, `ENABLE_USER_SCRIPT_SANDBOXING` unset, no Enhanced Security entitlements. Swift 6 readiness is low: `Task {}` captures non-Sendable `CAPPluginCall` and `BGAppRefreshTask`, and the `DateFormatter` static is a non-Sendable global.

**Fix.** Strict concurrency complete, warnings as errors, user-script sandboxing on, `ENABLE_ENHANCED_SECURITY = YES` with `ENABLE_POINTER_AUTHENTICATION = NO` (Capacitor / Cordova xcframeworks are arm64-only), hardened-process keys in both entitlement files. `.github/workflows/security.yml` never builds the iOS layer, so none of this is CI-gated.

## Found by running the app

### 34. Spaces vanish around rolling numbers (Medium)
`src/components/today/day-run-card.tsx:180`; `src/components/today/quest-card.tsx:64`

Seen in the simulator: the Today card reads "3to do · about40min" and the quest card reads "4of5rooms". Both lines split a translated string around a placeholder and render the fragments next to `RollingNumber` inside a `flex items-baseline` container. Each fragment becomes its own flex item, and CSS strips leading and trailing collapsible spaces at the edges of a flex item, so `" to do"`, `"about "`, `" of "` and `" rooms"` lose their spaces. The middle `&nbsp;·&nbsp;` survives only because it is non-breaking. Introduced with the "Numbers that move" commit (`34db74f`); visible on every launch for every user.

**Fix.** Drop `flex` from the two containers (the numbers are already `inline-flex` and sit on the baseline), or render the fragments with non-breaking spaces at their edges. Check `today-hero.tsx:207` and `run-strip.tsx:50` too; they are block or inline containers today and render correctly, but use the same split pattern.

## How the build was verified, and what was not

The full shipping pipeline was run on this Mac: `npm run build` → `npx cap sync ios` → clean Xcode build of the `App` scheme → install and launch on the iPhone 17 simulator → screenshot and OS-log check. That is the same sequence `npm run cap:sync` plus Xcode performs for a release, minus signing. Docker is not applicable here: the iOS app can only be built by Xcode on macOS, and the web half is already exercised by `.github/workflows/security.yml` on Ubuntu.

Not done: a Release archive or code-signed device build, TestFlight, the widget or the background weather refresh on a physical device, a VoiceOver pass on device. The control matrix's "NOT VERIFIED (manual)" rows remain manual.
